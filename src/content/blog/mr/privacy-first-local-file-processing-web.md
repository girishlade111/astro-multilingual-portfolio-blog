इंटरनेटवर फाईल अपलोड करताना आपण स्वतःला कधी हा प्रश्न विचारतो का—"ही फाईल नेमकी कोठे जात आहे?" जेव्हा तुम्ही सरकारी ओळखपत्र, बँकेचे स्टेटमेंट किंवा मेडिकल रिपोर्ट एखाद्या ऑनलाईन साईटवर अपलोड करता, तेव्हा तो डेटा तात्पुरता का होईना, दुसऱ्याच्या कॉम्प्युटरवर जात असतो.

मी जेव्हा **LS PDF** (https://lspdf.ladestack.in/) डिझाइन केले, तेव्हा माझा पहिला नियम हाच होता: वापरकर्त्याची फाईल त्यांच्या संगणकाबाहेर पडताच कामा नये.

## आधुनिक वेबचे ३ गुप्त हत्यार

ब्राउझर आता फक्त टेक्स्ट वाचण्याचे साधन राहिलेले नाही. खालील तीन तंत्रज्ञानांमुळे स्थानिक पातळीवर प्रचंड वेगाने काम करता येते:

1. **Web Workers**: फाईलवर प्रक्रिया करताना ब्राऊझरचा मेन थ्रेड अडकू नये (UI लॅग होऊ नये) यासाठी स्वतंत्र बॅकग्राउंड थ्रेडवर काम चालते.
2. **WebAssembly (WASM)**: C/C++ किंवा Rust मध्ये लिहिलेले हाय-स्पीड अल्गोरिदम थेट ब्राउझरमध्ये नेटिव्ह वेगाने रन होतात. PDF मर्जिंग आणि कॉम्प्रेशन यासाठी हे सर्वोत्तम आहे.
3. **Streams API**: मोठी फाईल मेमरीमध्ये एकाच वेळी लोड न करता चंक्स (लहान तुकड्यांमध्ये) प्रोसेस केली जाते.

```javascript
// क्लायंट-साइड सुरक्षित PDF रोटेशनचे उदाहरण
async function rotatePdfLocally(file) {
  const arrayBuffer = await file.arrayBuffer();
  // संपूर्ण प्रोसेसिंग स्थानिक मेमरीमध्येच होते
  const pdfDoc = await PDFDocument.load(arrayBuffer);
  const pages = pdfDoc.getPages();
  pages.forEach(page => page.setRotation(degrees(90)));
  const modifiedBytes = await pdfDoc.save();
  return new Blob([modifiedBytes], { type: 'application/pdf' });
}
```
