プログラミングを学び始めた頃、私にとって最大の関門の一つは「開発環境の構築」でした。スペックの高くないノートPCや、大学の実習室で共有されているPCを使っていると、Node.jsをインストールし、Pythonのパスを通し、VS Codeの拡張機能を入れ、GitのSSHキーを設定するだけで、コードを1行も書く前に何時間も溶けてしまいます。

私はその最初の大きな壁を取り払うために **GB Coder** (`code.ladestack.in`) を作りました。どんなモダンブラウザでも2秒で起動し、インテリセンスや構文診断が効き、本物のコードが動き、クラウドサーバーの管理や時間課金の仮想マシン代を一切気にしなくてよい開発スタジオを作ることが私の狙いでした。

この記事では、GB Coderの全体アーキテクチャ、設計における技術的トレードオフ、そしてデスクトップアプリに近い開発体験をブラウザ上でどのように実現したかを解説します。

## GB Coderを支える2層の実行エンジン

プロジェクトの目的によって、求められる実行環境はまったく異なります。HTMLとCSSの基本を学ぶ学生に重厚なLinuxターミナルは不要ですし、Reactのスターターキットを試したい開発者は `npm install` やローカル開発サーバーが動かなければ手も足も出ません。

軽快さと本格的な機能の両立を図るため、GB Coderには役割の異なる2つの実行モードを用意しました：

```text
┌────────────────────────────────────────────────────────┐
│                   GB Coder インターフェース            │
│         (Monaco Editor + ファイルツリー + タブ)        │
└───────────┬────────────────────────────────┬───────────┘
            │                                │
    [モード 1: 静的プレイグラウンド]  [モード 2: WebContainers]
            │                                │
    サンドボックス <iframe> プレビュー     Wasm製 Node.js カーネル
    双方向 postMessage 通信          仮想 POSIX ファイルシステム
    DOM への即時反映                 ローカルターミナル & npm サーバー
```

### 1. 軽量な静的Webプレイグラウンド

ちょっとしたWebコンポーネントの挙動を確かめるだけなら、仮想コンテナを立ち上げるのは資源の無駄遣いです。静的エンジンでは、VS Codeのコアでもある **Monaco Editor** と厳格に隔離された `<iframe>` を組み合わせています。

HTML、CSS、JavaScriptを編集すると：
- 不要な再計算を防ぐために変更がデバウンス（遅延評価）されます。
- メモリ上で単一のHTMLドキュメントとして即座に組み立てられます。
- iframe内に注入されたスクリプトが `console.log` や `console.error`、実行時例外をフックし、`postMessage` 経由でエディタ内のコンソールパネルへリアルタイムに転送します。

この動作は1ミリ秒未満で反映され、安価なスマートフォンや古いPCでもストレスなく動きます。

### 2. WebContainersによる本格的なNode.jsランタイム

フルスタックのコードを実行する際、GB CoderはStackBlitzが開発した **WebContainers** 技術を起動します。

WebContainersは、WebAssemblyをベースにしたマイクロOSをブラウザのWeb Workers内で直接動かす技術です。本物のNode.jsランタイム、仮想POSIXファイルシステム、模擬ネットワーク層がブラウザの中で動作します。対話型ターミナルを開いて `npm install` を叩き、CLIスクリプトを実行し、ViteやNext.jsなどのローカル開発サーバーを起動してプレビュー枠に画面を表示できます。

処理はすべて利用者のマシンのCPUで動きます。遠くのデータセンターでDockerコンテナを立ち上げる待ち時間も、放置したまま課金される心配も、キー入力から実行までのネットワーク遅延もありません。

## ブラウザ特有の厳しい制約をいかに乗り越えたか

ブラウザの1つのタブの中でIDEを動かすことには、デスクトップ版VS Codeでは決して起こり得ない特有の技術的難題が立ちはだかります。

### 1. Cross-Origin Isolation（クロスオリジン分離）の壁

WebContainersやマルチスレッドWebAssemblyを安全に動かすため、ブラウザは2つの厳格なHTTPヘッダーを要求します：

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

これらのヘッダーによって高精度タイマーや共有メモリ（`SharedArrayBuffer`）が有効化される一方、明示的な `CORP` ヘッダーを持たない外部CDN上のフォント、外部スクリプト、埋め込みリソースの読み込みが一切遮断されます。

この制限をクリアするため、Monaco Editorの言語ワーカー、シンタックス構文定義、アイコン等の全アセットを同一ドメイン配下で直接ホストし、外部CDNへの依存をゼロにする設計を行いました。

### 2. IndexedDBを用いた完全ローカルな永続化

ブラウザのタブは、誤って閉じられたり、再読み込みされたり、メモリ不足時にOSから強制終了されるリスクが常にあります。ユーザーに都度「保存」を押させたり外部DBへの同期を強いるのは、使い勝手の面でもデータ消失の面でも危険です。

GB Coderでは、ファイルの新規作成・変更・削除のすべてがブラウザ内の **IndexedDB** にトランザクションとして即座に書き込まれます：

```typescript
interface VirtualFile {
  path: string;
  content: string;
  updatedAt: number;
  isBinary: boolean;
}
```

仮にPCのバッテリーが切れて突然電源が落ちても、ページを再度開いた瞬間に以前のフォルダ階層、開いていたタブ、未保存のバッファが完全に復元されます。

ローカル環境へ移行したくなった場合は、ボタンを1回クリックするだけで `JSZip` を通じて全ファイルを標準の `.zip` 形式に圧縮し、GitHubや手元のディスクへ即座にエクスポートできます。

## コードに没頭するための細部のUI設計

エディタは何時間も画面を見つめ続ける道具です。小さな違和感が大きな疲労に直結します：

- **Monaco Workerの調整**: 構文チェックやIntelliSenseの推論を完全に独立したWeb Workerで行い、どんなにコードが長くなってもキー入力時の60fps描画を維持します。
- **目に優しいニュートラルカラー**: 亜鉛（zinc）系の落ち着いたトーンをベースに、明確なフォーカス枠と見やすいファイルアイコンを採用しました。
- **馴染み深いショートカット**: `Ctrl+P` によるファイルクイックオープン、`Ctrl+\` による画面分割、`Ctrl+\`` によるターミナル切り替えなど、標準的なキーバインドを忠実に再現しています。

## おわりに

GB Coderは、モダンWebブラウザが従来の限界を大きく突破したことの確かな証です。Monaco Editor、WebAssembly、そしてブラウザのローカル永続化機構を組み合わせることで、複雑な初期設定や毎月のサブスクリプション料金を課すことなく、開発者に強力な道具を届けることができるのです。
